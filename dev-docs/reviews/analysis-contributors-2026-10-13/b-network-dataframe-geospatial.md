# Stream B: correctness of gpu-network, gpu-dataframe subdirs, geospatial, src/utils

Repo `~/Documents/GitHub/vis.gl-build/luma-contributors`, live tree on 2026-10-13. Paths are relative to
`modules/experimental/src/`. Five Sonnet sub-reviews ran: B1 routing, B2 rest of network plus utils, B3 dataframe
plus geospatial, B4 a deep pass on the files B3 left, and B5 a library-wide pattern sweep. Their raw reports are in
`work/B/B1.md` to `B5.md`, and the oracle scripts are in `work/B/b1` to `b4`. The coordinator re-read the code for
every finding marked "C" in the table. Findings marked "S" were traced by a sub-reviewer and spot-read here. One
sub-review claim was refuted and is listed in §5. No GPU, headless or browser spec was run.

## 1. Verdict

There is no P0 in stream B. The shared helpers in `src/utils` are sound:
- Philox matches the three Random123 known-answer vectors.
- The WGSL mul-hi emulation matches BigInt on 2M pairs.
- The ordered-float key orders -inf < -0 < +0 < +inf < NaN.
- The kernel helper folds dispatch into three dimensions and checks the live storage-buffer limit.

The core reachability and frontier engine has no defect that we found. Barrier uniformity, the indirect caps,
"unreached = +Inf" and tie handling all trace correctly.

The defects are at the edges, in three families:
1. **Silent bounded approximations.** These are the map-matching route budget (much worse than the roadmap
   states), isochrones with no `converged` output, and a recipe that drops the snapping `overflow`.
2. **Per-edge tables that never write CSR tail slots.** Transient buffers can alias, so those slots hold stale
   data, not zero. In the K-function this emits an out-of-range node as a simulated event.
3. **Fixed-point and 64-bit word tricks that break at the extremes.** The variogram and correlogram scale collapses
   when the data has an outlier, the variogram pair count wraps at 2^32, and Int64 time comparison wraps when two
   times differ by 2^63 or more.

Library-wide, NaN tests written as `x == x` remain in about 16 of our files, including the shared exact-orientation
helper. They contradict the library's own `isNanBits` rule.

## 3. Patterns (library-wide) and the rule that prevents each

1. **NaN tested by self-compare or IEEE ordering in WGSL.** Our scope has about 36 such sites in about 16 files.
   - Examples: `geospatial` point-in-polygon and point-query helpers, `segment-intersection/exact-orientation-wgsl.ts:27` (`orientIsFinite`, shared by the exact-orientation callers), `segment-table.ts:136`, `point-density`, `cell-cover`, `location-allocation:524`, `kmeans:434/847`, `network-isochrones:124/275`, `flow-aggregation:137/610`.
   - About 160 files use the bit tests instead. There are also 18 local `isFiniteValue` re-definitions with differing semantics.
   - WGSL lets an implementation assume no NaN or Inf, and the library's own `isNanBits` doc says so.
   - This is latent today, because Metal specs pass. Under decision 4 ("NaN = missing"), though, a folded test classifies missing rows as valid.
   - **Rule:** every missing-value test uses `isNanBits` or `isFiniteBits` from `utils/wgsl-common.ts`, there are no local copies, and a lint grep rejects `\b(\w+) (==|!=) \1\b` inside WGSL template literals.
2. **Unwritten CSR tail slots** (B-03, B-04, B-09). There are 7 instances in 6 contributors plus 1 recipe. B5 checked about 20 other per-slot sites and found them guarded.
   - Transients alias, so "unwritten" means stale, not zero.
   - **Rule:** a node that owns an output writes all of its rows, and a per-edge loop is bounded by `offsets[NODE_COUNT]`, never by `neighbors.length`.
3. **Bounded approximation without a mandatory signal** (B-02, B-05, B-08, and the known K-function `overflow`). B5 audited 17 wrappers and recipes and found 3 that drop status.
   - **Rule:** any budget, capacity or unrolled loop puts its status word into the contributor's required output type, and a wrapper re-exports every inner status as a stage.
4. **Fixed-point or 64-bit word tricks at the extremes** (B-01, B-06, B-07).
   - **Rule:** never derive a rounding unit from the maximum.
   - **Rule:** a 64-bit accumulator reader saturates or returns both words.
   - **Rule:** order Int64 by comparing words with the sign bit flipped, not by the sign of a difference.
5. **Two engines, one statistic, different edge policies** (B-14, B-15 against networkx).
   - **Rule:** each statistic has one policy table (NaN, ±Inf, -0, out-of-range parameters, empty input) that every implementation and oracle imports.
6. **Accepted sizes that throw later** (B-18). There are about 75 `a * b` invocation counts, all routed through `getBoundedDispatchLayout`, so they fail cleanly but late.
   - **Rule:** the constructor validates `capacity × lanes ≤ 2^32 - 1`, or the kernel dispatches by live count.

## 4. Roadmap claims checked that are wrong or stale

- `gpu-analysis-algorithms-roadmap.md` P0: "`routeNodeBudget` overflow flag in map matching | Results are silently approximate today" (effort S). This is **worse than stated**. At 1 km sample spacing the default budget misses most routes in a grid mimic (B-02). Results are not "approximate"; they become breaks. A flag is necessary but not sufficient: the drop policy also needs fixing.
- `gpu-analysis-algorithms-roadmap.md` verdict: "Numerics are a strength … 64-bit fixed-point pair statistics". This is **partly wrong**. The variogram and correlogram scale is pegged to the extremes (B-01), and variogram counts wrap (B-06).
- `gpu-analysis-algorithms-roadmap.md` lists "reachability (chaotic Bellman-Ford with indirect gating)" as near-optimal. **Confirmed** for the engine, but `GPUNetworkIsochrones` does not surface its convergence (B-05).
- `gpugraph-roadmap.md` "GPU Core promotions": "The Philox RNG (`permutation-inference/permutation-random.ts`) … with separate copies in flow texture, particle advection and dot density". This is **stale**. Philox now lives in `utils/philox-random.ts` with 14 importers, and the Philox constants exist only there and in a CPU `multiplyHigh` helper in `permutation-random.ts`. What remains is a purpose-ID collision across modules (B-22), not code copies.
- `gpugraph-roadmap.md` "Line graph: ban lookup is O(arcs × bans)". This is accurate but understated: the scan runs in both the count pass and the fill pass (B-19).
- `gpugraph-roadmap.md` "Edge bundling … FDEB is O(E²) and stays rejected". **Confirmed**: the code is KDEEB (Hurter 2012), and B2 found no defect in it.

## 5. Unverified suspicions, and refuted claims

**Refuted:** B5-05 claimed that `straight-line-catchments-recipe.ts` drops the zonal `overflow`. It does omit the flag and returns `status: {stages: []}`, but `zoneCapacity = seedPositions.length` (:100) and the zone IDs are seed indices, so overflow cannot happen. At most this is a P3 note about the empty status.

**Unverified:**
- **K-means with NaN input** (`gpu-kmeans.ts:747`): `atomicMax` on the bits of a NaN `sqrt` result makes the state word NaN. If convergence is tested as `delta > tolerance`, poisoned data reports "converged". To confirm, read the convergence node (around :760-800) and run a NaN-position spec.
- **Workgroup storage at exactly 16384 bytes** (variogram with lag × direction = 512 plus the robust channel; Ripley distance functions with `radiusCount` 256): any further `var<workgroup>` breaks it on default-limit devices. To confirm, run one real-device spec at the maximum shape.
- **Ripley F lattice:** the 3 × 3 neighbour search needs `cellWidth >= maximumDistance`. Not checked in `pair-statistics-grid.ts`.
- **Variogram fitting on the CPU:** `fitVariogramModel` fits read-back bins. This is post-processing rather than a fallback, but it conflicts with the letter of the GPU-only policy. The owner should decide.
- **Map-matching route kernel cost:** each thread keeps a private table of about 1.5 KB and does an O(S) scan per pop. Occupancy is unmeasured; a quick A/B at S = 32, 64 and 128 would settle it.
- **`createWGSLKernelNode` bakes `${name}Offset` into the WGSL source.** Views at different offsets therefore compile distinct modules, which contradicts the helper's "source does not depend on problem size" comment and roadmap decision 1. Whole-buffer binds above `maxStorageBufferBindingSize` fail without a named error. To confirm, check how often the same kernel is compiled at two offsets in one showcase graph.
- **`getQuietNaN(seed)` = `0x7fc00000 | (seed & 0u)`:** it relies on the driver not folding the NaN away. A GPU spec that writes NaN and reads it back would confirm it, and would also settle pattern 1 on non-Metal backends.
